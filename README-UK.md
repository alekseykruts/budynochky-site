# Будиночки біля води — сайт та адміністрування

Поточний сайт збережено: його оформлення й усі 13 реальних фотографій залишилися. Додано карту відразу після Hero, маршрут, швидкі контакти та конфігурацію Decap CMS.

## Що вже готове

- Сайт у папці `dist/`. Для локального перегляду відкрийте `dist/index.html`.
- Сторінка `/admin/` та українські поля редактора.
- Єдине джерело даних: `content/site.json`.
- Автоматичне оновлення HTML, контактів, цін, карти, галереї та метаданих під час збірки.
- Налаштування GitHub backend і Netlify. Без підключення ваших акаунтів `/admin/` чесно показує інструкцію, а не імітує збереження.

## Одноразове підключення — без редагування коду

1. Розпакуйте архів. Створіть репозиторій GitHub і завантажте **вміст папки budynochky-site** через Add file → Upload files. `netlify.toml`, `package.json`, `content/`, `src/`, `cms/`, `scripts/` і `dist/` мають бути в корені репозиторію. Не завантажуйте лише ZIP або лише папку dist.
2. У Netlify: **Add new project → Import an existing project → GitHub**, виберіть репозиторій і Deploy. Команда збірки та папка сайту вже задані; вводити їх вручну не потрібно. Отримаєте адресу HTTPS на netlify.app.
3. У GitHub відкрийте https://github.com/settings/applications/new і створіть OAuth App. Назва — назва сайту; Homepage URL — отримана адреса Netlify; Authorization callback URL — `https://api.netlify.com/auth/done`.
4. У Netlify: **Project configuration → Access & security → OAuth → Install Provider → GitHub**. Внесіть Client ID та Client Secret створеного OAuth App. Секрет вводьте лише у Netlify, не у файли сайту.
5. Відкрийте **ваша-адреса/admin/** → «Увійти через GitHub» → **Керування сайтом → Вміст сайту**. Змініть потрібне поле та натисніть **Publish**. Дочекайтеся успішної публікації у Netlify й оновіть сторінку сайту.

Репозиторій та адресу сайту конфігурація підхопить автоматично під час першої збірки Netlify. Використовуйте імпорт із GitHub: перетягування лише готової сторінки через Netlify Drop не підключає CMS.

Редагувати можуть лише користувачі GitHub із правом запису до вашого репозиторію. Відвідувачі сайту не отримують права редагування.

## Що можна редагувати

| Розділ | Поля |
|---|---|
| Основна інформація | Назва, Hero, короткий опис, населений пункт, водойма |
| Контакти | Телефон, Viber, Telegram username, email |
| Ціни | Будні, вихідні, мінімум ночей, додатковий текст |
| Будиночки | Заголовок, опис, кількість місць, спільні зручності, список зручностей |
| Умови | Додавання, видалення, форматування й порядок пунктів |
| Як дістатися | Google Maps URL, координати, заголовок, вступ, форматована інструкція, текст кнопки |
| Фото | Завантаження, заміна, видалення з галереї, підписи, порядок, вибір Hero та секційних фото |

Порожній email приховується. Порожній Viber використовує основний телефон. Порожній Telegram username дає посилання за номером телефону; його відкриття залежить від налаштувань приватності Telegram.

У полі інструкції використовуйте абзаци, жирний/курсивний текст і списки. Поки інструкція порожня, зайвий блок не показується. Детальні повороти й орієнтири не вигадувалися.

## Фотографії

Відкрийте «Фотографії та галерея». Додавайте або перетягуйте пункти галереї; перші 5 показані у сітці, усі доступні у великому перегляді. Вибір Hero незалежний від порядку галереї.

Видалення пункту прибирає фото з галереї. Щоб видалити й сам файл у Медіа, спочатку приберіть його з усіх полів, де він використовується. Якщо видалено фото, яке ще потрібне Hero чи іншому блоку, перевірка не дозволить опублікувати зламану версію; попередній сайт залишається доступним.

Нові підтримувані зображення обробляються редактором зі збереженням пропорцій; наявні реальні фотографії не змінювалися. Decap CMS завантажується лише на сторінці адмінки після натискання входу. Головна сторінка не завантажує CMS.

## Перевірка й межі готовності

Успішно перевірено збірку зі зміною текстів, ціни, телефону, email, Telegram, координат, інструкції з форматуванням, умов, порядку галереї та Hero. Інтеграцію нового фото перевірено на копії наявного файлу. Також перевірено відсутність зламаних локальних шляхів, дубльованих ID, коректність посилань і синтаксис JS/CSS.

**Справжній вхід у GitHub, завантаження через CMS та Publish до Netlify ще не перевірені:** потрібне одноразове підключення ваших акаунтів.

**Браузерна перевірка desktop/mobile не завершена:** політика доступу вбудованого браузера заблокувала сторінку попереднього перегляду. Адаптивні стилі, safe-area та відступ під мобільною панеллю перевірено в коді, але це не замінює перевірку на екрані. Відкриття Viber, Telegram і Google Maps у встановлених застосунках також не підтверджувалося.

Приватне посилання ChatGPT Sites слугує поточним переглядом. Після підключення керуйте публічною версією за адресою Netlify; зміни з Netlify не синхронізують приватний перегляд ChatGPT автоматично.

## Для технічної підтримки

`node scripts/build-content.mjs` — збірка. `node scripts/check-content.mjs` — перевірка інтеграції контенту на тимчасовій копії, без зміни робочих даних. `dist/config.js` та `dist/index.html` генеруються автоматично. Правки через CMS потрапляють у `content/site.json`.

Збережено вихідний статичний проєкт. База даних та localStorage для зберігання контенту не використовуються. Секретів у проєкті немає.

Офіційні інструкції: [Decap GitHub backend](https://decapcms.org/docs/github-backend/), [Netlify OAuth](https://docs.netlify.com/manage/security/secure-access-to-sites/oauth-provider-tokens/), [Google Maps URLs](https://developers.google.com/maps/documentation/urls/get-started).

Підтверджені факти й ціни з попереднього етапу не переаналізовувалися. Координати та посилання Google Maps надані власником. Ліцензії локальних шрифтів — у dist/fonts/.
